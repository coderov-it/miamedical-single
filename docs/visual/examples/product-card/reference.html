    Why not 4 columns

    The same card at our current 4-up catalogue width (281px). The image keeps the same 4:3 ratio — only the foot has to stack and the name eats two lines. It survives — but the 3-up above is the reference proportion.

      Media standard — one frame, one master

      The display frame for product imagery is 4:3 everywhere — card stage, product-detail gallery, hero spotlight, cart thumbnail. The upload master is 1:1 square (the industry standard for product photography), rendered contained on the tint — never cropped, never stretched; the stage supplies the width. Video is the one 16:9 surface. Caps below mirror MEDIA_PROFILES in packages/validators/src/media.ts (the server already converts photos to WebP at max 2048px); the new rules are the 1:1 composition for photos and 1080p for video.

      Asset Ratio Recommended upload Rules
      Gallery photo 1:1 2048×2048 px (never below 1200×1200) · JPEG/PNG/WebP/AVIF White or neutral background, product fills 80–90% of the frame, sRGB. Server re-encodes to WebP ≤2048px.
      Thumbnail 1:1 Same standard — usually the first gallery shot The card renders it at ≤800px; never upload a small file for it.
      Clean PNG 1:1 2048×2048 px · PNG with transparency Cut-out product on transparent background, fills ~90%. Used on hero and tint stages.
      Video 16:9 1920×1080 (1080p) · MP4 H.264+AAC or WebM · ≤30 MB Stored as-is (no server conversion) — keep clips ~60–90 s.
      Icons 1:1 SVG preferred; raster lands 256×256 (icons) / ≤1024 (addons) Existing rule, unchanged — same 1:1 discipline as the photos.
      Documents — PDF · ≤15 MB Manuals and schede tecniche, stored as-is.

      To build it for real

      One data point, plus a token change.

      1. Spec tags — small API change. Specifications exist only on the product detail today. The list DTO needs the top 3 comparable ones, trimmed server-side.
      2. Type + ink tokens. The card family becomes self-hosted Inter, and the site's `--color-ink` softens to #2e3237 — no pure black anywhere.
